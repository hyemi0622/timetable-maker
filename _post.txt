<h4 data-ke-size="size20"><span style="color: #000000; background-color: #f6e199;">1. 활용한 핵심 기능</span></h4>
<p data-ke-size="size16">&nbsp;</p>
<p data-ke-size="size16">이 프로젝트는 프레임워크도 빌드 도구도 쓰지 않고 <b>순수 HTML + CSS + 바닐라 자바스크립트</b>로만 만들었습니다. 외부 의존성은 Pretendard 웹폰트와 OCR 라이브러리 두 개뿐입니다. 아래는 실제로 활용한 기능들입니다.</p>
<p data-ke-size="size16"><b>이미지 분석</b></p>
<ul data-ke-list-type="disc"><li><b>Canvas 2D Context의 getImageData()</b> : 이미지를 캔버스에 그린 뒤 픽셀 단위 RGBA 배열(<code>Uint8ClampedArray</code>)로 변환해 주는 메서드입니다. 이미지 처리의 출발점이며, 이 배열 하나로 모든 분석을 수행합니다.</li><li><b>Uint8Array (형식화 배열)</b> : 픽셀마다 "과목 블록인가 아닌가"를 0/1로 기록하는 마스크 버퍼로 사용했습니다. 일반 배열 대신 쓰면 <b>메모리를 1바이트씩만</b> 사용하고 접근 속도도 빠릅니다. 480×700 이미지면 33만 개 원소라 이 차이가 꽤 큽니다.</li><li><b>BFS(너비 우선 탐색)</b> : 마스크에서 서로 붙어 있는 픽셀 덩어리를 하나의 과목 블록으로 묶는 연결 요소 검출에 사용했습니다.</li><li><b>히스토그램 최빈값(mode)</b> : 이미지에서 가장 많이 등장하는 밝기를 배경색으로 간주합니다. 이것 하나로 <b>라이트 모드와 다크 모드를 같은 코드로</b> 처리합니다.</li><li><b>백분위수(percentile) 기반 동적 임계값</b> : 고정된 숫자 대신, 그 이미지의 밝기 분포에서 임계값을 매번 계산합니다.</li><li><b>Tesseract.js</b> : OCR 라이브러리입니다. 단, 통째로 던지지 않고 <b>영역을 직접 나눈 뒤</b> 부분적으로만 사용했습니다.</li></ul>
<p data-ke-size="size16"><b>렌더링 · 입출력</b></p>
<ul data-ke-list-type="disc"><li><b>Canvas 2D Path API</b> : <code>beginPath</code> / <code>moveTo</code> / <code>lineTo</code> / <code>stroke</code> / <code>fill</code> 로 시간표를 DOM이 아닌 캔버스에 직접 그렸습니다. DOM으로 그리면 이미지로 저장할 때 html2canvas 같은 추가 라이브러리가 필요한데, 처음부터 캔버스에 그리면 <code>toBlob()</code> 한 줄로 끝납니다.</li><li><b>ctx.clip()</b> : 특정 경로 안쪽으로만 그리기를 제한합니다. 과목 글자가 박스 밖으로 삐져나오지 않게 하는 데 썼습니다.</li><li><b>ctx.toBlob() + URL.createObjectURL()</b> : 캔버스를 이미지 파일(Blob)로 바꾸고 다운로드로 연결하는 조합입니다. <code>toDataURL()</code>보다 메모리 효율이 좋습니다.</li><li><b>Pointer Events</b> : <code>pointerdown</code> / <code>pointermove</code> / <code>pointerup</code> 하나로 마우스와 터치를 <b>동시에</b> 처리합니다. mousedown과 touchstart를 따로 쓸 필요가 없습니다.</li><li><b>touch-action CSS 속성</b> : 브라우저의 기본 터치 동작(스크롤·확대)을 어디까지 허용할지 지정합니다.</li><li><b>devicePixelRatio</b> : 기기의 물리 픽셀 밀도입니다. 레티나 화면에서 캔버스가 흐려지지 않게 하는 데 필수입니다.</li><li><b>ImageData + 플러드 필(Flood Fill)</b> : 캐릭터 배경 제거에 사용한 알고리즘입니다.</li></ul>

<h4 data-ke-size="size20"><span style="color: #000000; background-color: #f6e199;">3. 시간표 이미지 파싱</span></h4>
<p data-ke-size="size16">&nbsp;</p>
<p data-ke-size="size16">제일 재밌었고 제일 오래 걸린 부분입니다. 이미지 한 장에서 과목의 <b>요일 / 시작시각 / 종료시각 / 수업명 / 강의실</b>을 뽑아내야 했습니다. OCR 라이브러리에 통째로 던지지 않았습니다. 에타 시간표는 구조가 정해져 있으니 구조를 이용하는 게 훨씬 정확하다고 판단했습니다.</p>
<p data-ke-size="size18"><span style="color: #000000; background-color: #dddddd;">3-1. 배경 밝기 추정 - 라이트/다크 모드 자동 판별</span></p>
<p data-ke-size="size16">가장 먼저 한 일은 <b>이 이미지의 배경색이 무엇인가</b>를 알아내는 것이었습니다. 에타는 다크 모드를 지원하기 때문에 배경이 흰색일 수도 있고 거의 검은색일 수도 있습니다.</p>
<pre class="javascript" data-ke-type="codeblock" data-ke-language="javascript"><code>// 이미지 전체를 2픽셀 간격으로 샘플링해서 밝기 히스토그램을 만든다
const hist = new Array(32).fill(0);
for (let j = 0; j &lt; H; j += 2) for (let i = 0; i &lt; W; i += 2) {
  const c = at(i, j);
  hist[((c[0] + c[1] + c[2]) / 3 / 8) | 0]++;   // 0~255를 32구간으로 압축
}
// 가장 빈도가 높은 구간 = 배경 밝기
const bgV = hist.indexOf(Math.max(...hist)) * 8 + 4;</code></pre>
<p data-ke-size="size16">시간표 이미지는 면적의 대부분이 배경이므로 <b>최빈값을 찾으면 그게 곧 배경색</b>입니다. <code>| 0</code>은 비트 연산을 이용한 정수 변환으로 <code>Math.floor()</code>보다 빠릅니다.</p>
<p data-ke-size="size16">이 <code>bgV</code> 하나를 구해 두면 그 다음부터는 "배경과 다른가?"만 따지면 되기 때문에, 라이트/다크를 구분하는 분기문이 아예 필요 없어집니다.</p>
<p data-ke-size="size18"><span style="color: #000000; background-color: #dddddd;">3-2. 과목 블록 찾기 - 마스크 + BFS</span></p>
<p data-ke-size="size16">배경을 알았으니 이제 과목 블록을 찾습니다. 조건은 두 가지 중 하나만 만족하면 됩니다.</p>
<pre class="javascript" data-ke-type="codeblock" data-ke-language="javascript"><code>const mask = new Uint8Array(W * H);
for (let j = 0; j &lt; H; j++) for (let i = 0; i &lt; W; i++) {
  const [r, g, b] = at(i, j);
  const mx = Math.max(r, g, b), mn = Math.min(r, g, b), v = (r + g + b) / 3;
  // (1) 채도가 있는 색이거나  (2) 배경과 밝기가 확실히 다르면 과목 블록
  if ((mx - mn &gt; 8 || Math.abs(v - bgV) &gt; 40) &amp;&amp; mx &gt; 60) mask[j * W + i] = 1;
}</code></pre>
<p data-ke-size="size16"><code>mx - mn</code>은 <b>채도(saturation)</b>에 해당합니다. RGB 중 최댓값과 최솟값의 차이가 크면 유채색이라는 뜻입니다. 일반적인 파스텔 과목 색은 이 조건에 걸립니다.</p>
<p data-ke-size="size16">(2)번 조건이 중요한데, <b>거의 흰색에 가까운 연한 파스텔</b>(예: #F6EAEA)은 채도가 낮아서 (1)번만으로는 못 잡습니다. 이때 "배경과 밝기가 다르다"는 조건이 구해 줍니다. 임계값을 40으로 둔 이유는 격자선(배경과 14 정도 차이)을 걸러내기 위해서입니다.</p>
<p data-ke-size="size16">마스크를 만들었으면 BFS로 덩어리를 찾습니다.</p>
<pre class="javascript" data-ke-type="codeblock" data-ke-language="javascript"><code>const seen = new Uint8Array(W * H), comps = [];
for (let p = 0; p &lt; W * H; p++) {
  if (!mask[p] || seen[p]) continue;
  let qs = [p]; seen[p] = 1;
  let x0 = 1e9, y0 = 1e9, x1 = -1, y1 = -1, n = 0;
  while (qs.length) {
    const q = qs.pop(), qi = q % W, qj = (q / W) | 0;
    n++;
    x0 = Math.min(x0, qi); x1 = Math.max(x1, qi);   // 바운딩 박스 갱신
    y0 = Math.min(y0, qj); y1 = Math.max(y1, qj);
    for (const [di, dj] of [[1,0],[-1,0],[0,1],[0,-1]]) {   // 4방향 탐색
      ...
    }
  }
  const w = x1 - x0 + 1, h = y1 - y0 + 1;
  // 너무 작거나, 속이 성긴 덩어리(격자선 등)는 버린다
  if (n &gt; 250 &amp;&amp; w &gt; 18 &amp;&amp; h &gt; 12 &amp;&amp; n / (w * h) &gt; .40) comps.push({ x0, y0, x1, y1, w, h });
}</code></pre>
<p data-ke-size="size16">마지막 필터가 핵심입니다. <code>n / (w * h)</code>는 <b>바운딩 박스를 얼마나 꽉 채우고 있는지(채움 비율)</b>입니다. 과목 블록은 사각형이라 이 값이 높지만, 격자선이 연결되어 만들어진 덩어리는 속이 텅 비어 있어서 값이 낮습니다.</p>
<p data-ke-size="size16"><b>이 임계값을 처음에 0.55로 잡았다가 버그를 겪었습니다. 교수명·강의실 글자가 많은 과목은 글자가 블록 안에 구멍을 내기 때문에 채움 비율이 떨어져서 <b>블록이 통째로 버려졌습니다.</b> 0.40으로 낮춰서 해결했습니다.</b></p>
<p data-ke-size="size18"><span style="color: #000000; background-color: #dddddd;">3-3. 요일 열 찾기 - 세로 격자선을 직접 검출</span></p>
<p data-ke-size="size16">처음에는 검출된 블록들의 x좌표를 클러스터링해서 열 간격을 역산했습니다. 그런데 치명적인 버그가 있었습니다.</p>
<p data-ke-size="size16"><b><b>목요일에 수업이 하나도 없으면, 금요일 과목이 목요일 칸으로 들어갑니다.</b></b></p>
<p data-ke-size="size16">블록이 있는 열(월·화·수·금)만 보고 간격을 계산하니 전체가 한 칸씩 밀린 것입니다. 그래서 <b>이미지에서 세로 격자선 자체를 찾는 방식</b>으로 바꿨습니다.</p>
<pre class="javascript" data-ke-type="codeblock" data-ke-language="javascript"><code>// 그리드 영역을 세로로 스캔하면서, 회색 선이 세로로 길게 이어지는 x좌표를 찾는다
for (let i = 1; i &lt; W - 1; i++) {
  let cnt = 0;
  for (let j = yA; j &lt;= yB; j++) {
    const [r, g, b] = at(i, j), v = (r + g + b) / 3, dv = Math.abs(v - bgV);
    // 무채색(r≈g≈b)이면서 배경과 살짝만 다른 픽셀 = 격자선
    if (Math.abs(r - g) &lt; 14 &amp;&amp; Math.abs(g - b) &lt; 14 &amp;&amp; dv &gt; 4 &amp;&amp; dv &lt; 80) cnt++;
  }
  if (cnt &gt; (yB - yA) * .6) vraw.push(i);   // 60% 이상 이어지면 선으로 인정
}

// 인접 간격의 중앙값 = 열 너비
const sorted = [...gaps2].sort((a, b) =&gt; a - b), med = sorted[sorted.length &gt;&gt; 1];
const nDay = gaps2.filter(g2 =&gt; Math.abs(g2 - med) &lt; med * .25).length;
// 요일 칸이 4~7개로 나올 때만 신뢰하고, 아니면 기존 방식으로 fallback
if (k0 &gt;= 0 &amp;&amp; nDay &gt;= 4 &amp;&amp; nDay &lt;= 7 &amp;&amp; med &gt; W * .08) { colW = med; gridL = vl[k0]; }</code></pre>
<p data-ke-size="size16">여기서 <b>평균이 아니라 중앙값(median)을 쓴 점</b>이 포인트입니다. 선이 하나 잘못 검출되어도 중앙값은 흔들리지 않습니다.</p>
<p data-ke-size="size16">마지막 줄의 <code>nDay >= 4 && nDay <= 7</code> 조건도 중요합니다. 비전 처리는 언제든 실패할 수 있으므로, <b>결과가 상식적인 범위를 벗어나면 이전 방식으로 되돌아가도록</b> 안전망을 걸어 두었습니다.</p>
<p data-ke-size="size18"><span style="color: #000000; background-color: #dddddd;">3-4. 붙어 있는 두 과목 분리하기 - 세 번 갈아엎은 부분</span></p>
<p data-ke-size="size16">에타에서 9:00~10:30 수업과 10:30~12:00 수업이 연달아 있을 때, <b>두 블록의 색이 같으면 픽셀상 경계가 존재하지 않습니다.</b> BFS 입장에서는 하나의 덩어리입니다.</p>
<p data-ke-size="size16"><b>1차 시도 - 색 차이로 끊기</b></p>
<p data-ke-size="size16">플러드필 중 인접 픽셀의 색차가 크면 연결을 끊도록 했습니다. 실패했습니다. 실제 픽셀을 찍어 보니 두 과목의 색이 <code>rgb(194,209,204)</code>로 <b>완전히 동일</b>했습니다.</p>
<p data-ke-size="size16"><b>2차 시도 - 글자 덩어리 위치로 끊기</b></p>
<p data-ke-size="size16">블록 안에서 행별 글자 픽셀 수를 세어 "텍스트 뭉치"를 찾고, 뭉치가 2개 이상이면 그 사이를 자르도록 했습니다. 수업명만 표시하는 시간표에서는 완벽하게 동작했습니다.</p>
<p data-ke-size="size16"><b>3차 - 부가정보가 들어오자 또 깨짐</b></p>
<p data-ke-size="size16">에타는 설정에 따라 <code>수업명 / 교수명 / 장소</code>를 전부 보여줍니다. 그러면 글자 줄이 촘촘해져서 과목 경계가 묻히고, 반대로 부가정보 줄 사이 간격을 과목 경계로 오인하기도 했습니다.</p>
<p data-ke-size="size16"><b>최종 해법 - 진한 글씨만 본다</b></p>
<p data-ke-size="size16">에타를 자세히 보니 <b>수업명만 굵고 진하고, 교수명·장소는 연합니다.</b> 이 성질을 쓰기로 했습니다.</p>
<pre class="javascript" data-ke-type="codeblock" data-ke-language="javascript"><code>// 블록 안에서 &#x27;글자&#x27;에 해당하는 픽셀들의 밝기를 전부 모은다
const vs = [];
for (let j = m.y0; j &lt;= m.y1; j++) for (let i = m.x0; i &lt;= m.x1; i++) {
  const c2 = at(i, j), v = (c2[0] + c2[1] + c2[2]) / 3;
  if (v &lt; bv0 - 18) vs.push(v);     // 블록 색보다 어두우면 글자
}
vs.sort((p2, q2) =&gt; p2 - q2);
const p5  = vs[(vs.length * .05) | 0];     // 하위 5% (가장 진한 쪽)
const p50 = vs[vs.length &gt;&gt; 1];            // 중앙값
const th  = p5 + (p50 - p5) * .55;         // 그 사이 지점을 임계값으로</code></pre>
<p data-ke-size="size16">고정 임계값이 아니라 <b>그 블록의 밝기 분포에서 매번 계산</b>합니다. 이러면 시간표 색이 무엇이든 상관없습니다. 이 <code>th</code>보다 어두운 픽셀(= 수업명)만으로 프로파일을 만드니 과목 경계가 선명해졌습니다.</p>
<p data-ke-size="size16">여기에 안전장치를 두 개 더 걸었습니다.</p>
<pre class="javascript" data-ke-type="codeblock" data-ke-language="javascript"><code>// (1) 분할 지점이 30분 격자에 맞을 때만 자른다 (실제 수업 경계는 반드시 정각/30분)
const u = (y - top) / pitch * 2;
if (Math.abs(u - Math.round(u)) &gt; .38) continue;

  cuts.push(snap);</code></pre>
<p data-ke-size="size16">(2)번이 없으면 <code>데이터베이스 / 개론</code>처럼 수업명이 두 줄인 과목이 두 개로 쪼개집니다. 실제로 겪었던 버그입니다.</p>
<p data-ke-size="size18"><span style="color: #000000; background-color: #dddddd;">3-5. 시작 시각이 통째로 15분씩 밀리는 문제</span></p>
<p data-ke-size="size16">15분 단위 인식을 추가했더니 9:00 수업이 <b>9:15로 나오기 시작</b>했습니다. 원인은 단순했습니다.</p>
<p data-ke-size="size16"><b>에타는 과목 블록을 셀 경계에 딱 붙이지 않고, <b>위쪽에 여백을 두고</b> 그립니다.</b></p>
<p data-ke-size="size16">30분 단위로 반올림할 땐 그 여백이 묻혔는데, 15분으로 잘게 쪼개니 드러난 것입니다. 두 가지로 해결했습니다.</p>
<pre class="javascript" data-ke-type="codeblock" data-ke-language="javascript"><code>// (1) 모든 블록이 &#x27;얼마나 밀렸는지&#x27; 소수부를 모아서, 그 중앙값만큼 기준선을 내린다
const offs = comps.map(m =&gt; {
  const u = (m.y0 - top) / pitch;
  return u - Math.floor(u);          // 격자에서 벗어난 정도 (0~1)
}).sort((a, b) =&gt; a - b);
const medOff = offs[offs.length &gt;&gt; 1];
if (medOff &gt; .02 &amp;&amp; medOff &lt; .3) top += medOff * pitch;

// (2) 30분 격자에 가까우면 30분 유지, 확실히 벗어날 때만 15분 스냅
const q = v =&gt; {
  const half = Math.round(v * 2) / 2;
  return Math.abs(v - half) &lt; .2 ? half : Math.round(v * 4) / 4;
};</code></pre>
<p data-ke-size="size16">여기서도 <b>중앙값</b>을 쓰는 게 핵심입니다. 진짜로 9:15에 시작하는 수업이 하나 섞여 있어도 전체 보정값이 틀어지지 않습니다.</p>
<p data-ke-size="size18"><span style="color: #000000; background-color: #dddddd;">3-6. OCR - 라이브러리에 통째로 던지지 않기</span></p>
<p data-ke-size="size16">수업명과 강의실을 구분하는 데 처음에는 Tesseract가 돌려주는 줄 높이(bbox)를 썼습니다. 결과는 처참했습니다.</p>
<pre class="plain" data-ke-type="codeblock" data-ke-language="plain"><code>수업명   : &quot;상주캠퍼스 제5&quot;
부가정보 : &quot;객체지향언어 서정훈 호관-207&quot;</code></pre>
<p data-ke-size="size16">완전히 뒤바뀌었습니다. 한글은 받침 유무에 따라 줄 높이가 들쭉날쭉해서 신뢰할 수 없었던 겁니다. 그래서 <b>OCR에 던지기 전에, 우리가 픽셀로 직접 영역을 나누는 방식</b>으로 바꿨습니다.</p>
<pre class="javascript" data-ke-type="codeblock" data-ke-language="javascript"><code>// 1) 블록을 3배 확대 + 대비 강화해서 인식률을 올린다
const up = 3;
cx.filter = &#x27;grayscale(1) contrast(1.8) brightness(1.08)&#x27;;
cx.drawImage(img, bx.x0*k, bx.y0*k, bx.w*k, bx.h*k, 0, 0, W2, H2);

// 2) 행별 글자 픽셀을 세서 &#x27;글자 줄&#x27; 구간들을 찾는다
const allRuns  = rowsOf(175);                      // 모든 글자 줄
const darkRuns = rowsOf(p5 + (p50 - p5) * .45);    // 진한 글자 줄만

// 4) 바로 아래 줄이라도 진하기가 확 연해지면 거기서 끊는다

<p data-ke-size="size16">처음에는 줄 간격만으로 나눴는데, 수업명 바로 밑에 강의실이 딱 붙어 있으면 그걸 "수업명 두 번째 줄"로 오인했습니다. 줄 간격 대신 <b>진하기</b>를 기준으로 바꾸자 해결됐습니다. 실제 캡쳐본으로 검증한 결과입니다.</p>
<pre class="plain" data-ke-type="codeblock" data-ke-language="plain"><code>웹프로그래밍1        | 송치양 상주캠퍼스 제5 호관-309

<p data-ke-size="size16">여기서 얻은 교훈이 있습니다. <b>OCR은 만능이 아니고, 구조를 아는 쪽은 내 코드입니다.</b> 어디까지가 제목이고 어디부터가 부속 정보인지는 라이브러리보다 제가 더 잘 알고 있었습니다.</p>
<p data-ke-size="size16">다만 글자 자체의 오독(<code>개론</code> → <code>개로</code>)은 여전히 남습니다. Tesseract의 한계라 코드로는 밀어낼 수 없었습니다. 그래서 <b>미리보기에서 과목을 탭하면 수업명·강의실·요일·시간을 즉시 고칠 수 있는 편집 UI</b>를 따로 만들어 두었습니다.</p>
<pre class="javascript" data-ke-type="codeblock" data-ke-language="javascript"><code>// 시간 입력은 &lt;input type=&quot;time&quot; step=&quot;900&quot;&gt; 으로 15분 단위 네이티브 피커를 띄운다
const toHM  = v =&gt; `${String(Math.floor(v)).padStart(2,&#x27;0&#x27;)}:${String(Math.round((v%1)*60)).padStart(2,&#x27;0&#x27;)}`;

<p data-ke-size="size16"><code>type="time"</code>을 쓰면 모바일에서 OS 기본 시간 선택기가 떠서, 별도 UI를 만들지 않고도 터치로 편하게 수정할 수 있습니다. <code>step="900"</code>(초 단위)으로 15분 간격을 지정했습니다.</p>

<h4 data-ke-size="size20"><span style="color: #000000; background-color: #f6e199;">4. 손그림 선 렌더링</span></h4>
<p data-ke-size="size16">&nbsp;</p>
<p data-ke-size="size16">"꾸불꾸불한 손그림 느낌"을 내려면 직선에 노이즈를 줘야 합니다. 그런데 <code>Math.random()</code>을 쓰면 안 됩니다.</p>
<p data-ke-size="size16"><b>같은 선은 <b>언제 다시 그려도 똑같이 꾸불거려야</b> 합니다. 매번 랜덤이면 과목 박스와 격자선이 서로 어긋납니다.</b></p>
<p data-ke-size="size18"><span style="color: #000000; background-color: #dddddd;">4-1. 결정론적 노이즈(value noise)</span></p>
<pre class="javascript" data-ke-type="codeblock" data-ke-language="javascript"><code>// 의사 난수: 같은 n이면 항상 같은 값 (0~1)
const rnd = n =&gt; {
  const v = Math.sin(n * 127.1 + 311.7) * 43758.5453;
  return v - Math.floor(v);     // 소수부만 취해서 0~1로
};

// value noise: seed와 좌표 t가 같으면 항상 같은 흔들림 값
function jit(seed, t, amp) {
  const s = t / WAVE, i = Math.floor(s), f = s - i;
  const u = f * f * (3 - 2 * f);           // smoothstep (부드러운 보간)
  const a = rnd(seed + i), b = rnd(seed + i + 1);
  return ((a + (b - a) * u) * 2 - 1) * amp;
}</code></pre>
<p data-ke-size="size16"><code>Math.sin()</code>의 소수부를 취하는 건 셰이더에서 자주 쓰는 의사 난수 기법입니다. <b>같은 입력이면 항상 같은 출력</b>이라 재현 가능합니다. smoothstep(<code>f*f*(3-2*f)</code>)으로 보간하는 이유는, 선형 보간을 쓰면 노이즈 격자 지점에서 선이 각지게 꺾이기 때문입니다.</p>
<figure class="imageblock alignCenter" data-ke-type="image"><span><img src="https://hyemi0622.github.io/timetable-maker/images/04-handdrawn-line.png" alt="일반 격자와 value noise를 적용한 손그림 격자 비교" /></span><figcaption>일반 격자와 value noise를 적용한 손그림 격자 비교</figcaption></figure>
<p data-ke-size="size16">세로선은 <b>y좌표를 입력</b>으로, 가로선은 <b>x좌표를 입력</b>으로 흔들리게 했습니다. 이렇게 하면 선의 일부 구간만 그려도 전체 선과 위상이 정확히 맞습니다.</p>
<pre class="javascript" data-ke-type="codeblock" data-ke-language="javascript"><code>// 세로선: y를 따라가며 x를 흔든다
function vSeg(x, y0, y1, seed, amp) {
  const p = [], n = Math.max(2, Math.ceil((y1 - y0) / 7));
  for (let i = 0; i &lt;= n; i++) {
    const y = y0 + (y1 - y0) * i / n;
    p.push([x + jit(seed, y, amp), y]);
  }
  return p;
}</code></pre>
<p data-ke-size="size18"><span style="color: #000000; background-color: #dddddd;">4-2. 선 굵기가 일정하지 않다 - 다섯 번의 실패 기록</span></p>
<p data-ke-size="size16">이 프로젝트에서 <b>가장 오래 붙잡은 문제</b>입니다. "선 굵기가 들쭉날쭉하다"는 같은 증상인데, 원인이 매번 달랐습니다.</p>
<p data-ke-size="size16"><b>실패 1 - 과목 박스가 격자선을 덮음</b></p>
<p data-ke-size="size16">처음에는 <code>격자 → 박스</code> 순서로 그렸습니다. 박스를 나중에 칠하니 <b>과목 칸 안의 격자선이 사라졌습니다.</b></p>
<p data-ke-size="size16"><b>실패 2 - seed가 한 칸씩 어긋남</b></p>
<p data-ke-size="size16">박스의 좌우 세로선과 격자선이 <b>서로 다른 파형</b>으로 흔들리고 있었습니다.</p>
<pre class="javascript" data-ke-type="codeblock" data-ke-language="javascript"><code>// 격자선   : x = g.x + g.timeW + j * g.colW,  seed = j + 40
// 박스(버그): 왼쪽 seed = day + 39, 오른쪽 seed = day + 40   ← 전부 한 칸씩 밀림
// 수정      : 왼쪽 seed = day + 40, 오른쪽 seed = day + 41</code></pre>
<p data-ke-size="size16">한 칸 밀린 seed를 쓰니 박스 테두리와 격자선이 미묘하게 다른 곡선을 그렸고, 겹치는 구간은 두껍게, 벌어지는 구간은 틈이 생겼습니다.</p>
<p data-ke-size="size16"><b>실패 3 - 맞닿은 과목의 경계선을 두 번 그림</b></p>
<p data-ke-size="size16">월요일 9:00~10:30 수업과 10:30~12:00 수업이 붙어 있으면, 10:30 선을 <b>위 과목이 "내 아래쪽 선"으로 한 번, 아래 과목이 "내 위쪽 선"으로 한 번</b> 그리고 있었습니다. 게다가 seed가 과목 순번 기반이라 두 선의 파형도 달랐습니다.</p>
<pre class="javascript" data-ke-type="codeblock" data-ke-language="javascript"><code>// seed를 &#x27;요일 + 시각&#x27; 기반으로 통일 → 누가 그리든 같은 파형이 나온다
const es = (day, t) =&gt; day * 97 + Math.round((t - S.startHour) * 2) * 7 + 700;

// 이미 그린 경계는 Set으로 건너뛴다
const drawn = new Set();
const key = day + &#x27;:&#x27; + t;
if (drawn.has(key)) return;
drawn.add(key);</code></pre>
<p data-ke-size="size16"><b>실패 4 - 박스가 선의 '절반'을 덮음</b></p>
<p data-ke-size="size16">실패 1을 고치려고 박스를 선 두께의 절반만큼 안쪽으로 좁혀서 칠했습니다. 그런데 <b>꾸불거리는 선은 위치가 계속 흔들리기 때문에</b>, 어떤 구간은 절반이 덮이고 어떤 구간은 안 덮였습니다. 결국 또 들쭉날쭉.</p>
<p data-ke-size="size16">최종적으로는 이렇게 정리했습니다.</p>
<pre class="javascript" data-ke-type="codeblock" data-ke-language="javascript"><code>// 1) 과목 박스를 먼저 채운다 (경계까지 꽉, 좁히지 않음)
// 2) 선을 그 위에 그린다  → 칠하기가 선을 덮을 일이 없다
// 3) 시간선이 과목 &#x27;안쪽&#x27;을 지나는 구간은 아예 건너뛴다
for (let dd = 0; dd &lt; g.days; dd++) {
  const cx0 = g.x + g.timeW + dd * g.colW;
  if (S.items.some(it =&gt; it.day === dd &amp;&amp; it.s &lt; t &amp;&amp; t &lt; it.e)) {
    if (from !== null &amp;&amp; cx0 &gt; from) poly(hSeg(y, from, cx0, sd, g.amp));
    from = null;                        // 이 칸은 건너뛰고
  } else if (from === null) from = cx0; // 다음 칸부터 다시 시작
}
if (from !== null) poly(hSeg(y, from, g.x + g.tw, sd, g.amp));</code></pre>
<p data-ke-size="size16">화요일 9시~13시 수업이 있으면 그 칸의 10·11·12시 선은 <b>애초에 그리지 않고</b>, 양옆 요일은 하나의 연속된 선으로 이어서 그립니다. 겹치는 곳도, 절반만 덮이는 곳도 사라졌습니다.</p>
<p data-ke-size="size16"><b>실패 5 - 그런데 아직도 들쭉날쭉하다</b></p>
<p data-ke-size="size16">코드를 네 번 고쳤는데 눈으로는 여전했습니다. 그래서 <b>추측을 멈추고 실제 캔버스 픽셀을 직접 측정</b>했습니다.</p>
<pre class="javascript" data-ke-type="codeblock" data-ke-language="javascript"><code>// 가로선 위아래로 어두운 픽셀이 몇 개나 연속되는지 센다
const meas = (x, yc) =&gt; {
  let n = 0;
  for (let y = yc - 25; y &lt; yc + 25; y++) if (dark(x, y)) n++;
  return n;
};
// 결과: [16, 8, 7, 8, 8, 8, 8, 8, 8, 7, 8, 8]   ← 7~8px로 이미 균일했음</code></pre>
<p data-ke-size="size16"><b>렌더링은 처음부터 정상이었습니다.</b> 진짜 범인은 미리보기였습니다. 1179px 캔버스를 CSS로 211px까지 <b>5.6배 축소</b>해서 보여주고 있었고, 브라우저가 축소하면서 어떤 선은 1px, 어떤 선은 2px로 뭉갰던 것입니다. 꾸불거리는 선이라 각 부분이 픽셀 격자에 다르게 떨어져 더 두드러졌습니다.</p>
<pre class="javascript" data-ke-type="codeblock" data-ke-language="javascript"><code>// 미리보기는 &#x27;화면 해상도로 직접&#x27; 렌더링 → 축소 과정 자체를 없앤다
function fitStage() {
  const box = cv.parentElement.clientWidth || (window.innerWidth - 56);
  const w = Math.min(360, box), ar = S.device[1] / S.device[2], h = w / ar;
  const dpr = Math.min(3, window.devicePixelRatio || 1);
  cv.width  = Math.round(w * dpr);     // 실제 픽셀 수
  cv.height = Math.round(h * dpr);
  cv.style.width  = w + &#x27;px&#x27;;          // CSS 표시 크기
  cv.style.height = h + &#x27;px&#x27;;
}

// 저장할 때만 기기 해상도로 키워서 다시 그린다
cv.width = S.device[1]; cv.height = S.device[2];
draw();
cv.toBlob(b =&gt; { ... }, &#x27;image/jpeg&#x27;, .95);</code></pre>
<p data-ke-size="size16">캔버스의 <code>width</code> 속성(실제 픽셀)과 <code>style.width</code>(화면 표시 크기)를 분리하는 건 레티나 대응의 기본인데, 이걸 놓치고 있었습니다.</p>
<p data-ke-size="size16"><b><b>교훈</b> : 증상이 안 고쳐지면 측정부터. 네 번째 수정까지는 "보이는 것"을 고치고 있었는데, 실제로 고쳐야 할 건 완전히 다른 레이어였습니다.</b></p>

<h4 data-ke-size="size20"><span style="color: #000000; background-color: #f6e199;">5. 캐릭터 누끼(배경 제거) - 플러드 필</span></h4>
<p data-ke-size="size16">&nbsp;</p>
<p data-ke-size="size16">캐릭터 사진을 올리면 배경을 지워서 스티커처럼 붙일 수 있게 했습니다. <b>AI API를 쓰지 않고</b> 플러드 필로 직접 구현했습니다.</p>
<figure class="imageblock alignCenter" data-ke-type="image"><span><img src="https://hyemi0622.github.io/timetable-maker/images/03-cutout.png" alt="배경 제거 전/후 (투명 영역은 체크무늬로 표시)" /></span><figcaption>배경 제거 전/후 (투명 영역은 체크무늬로 표시)</figcaption></figure>
<pre class="javascript" data-ke-type="codeblock" data-ke-language="javascript"><code>// 1) 이미지 네 변의 테두리 픽셀을 전부 시작점(seed)으로 큐에 넣는다
for (let i = 0; i &lt; W; i++) { push(i); push((H-1)*W + i); }
for (let j = 0; j &lt; H; j++) { push(j*W); push(j*W + W-1); }

// 2) 배경색과 비슷한 픽셀을 따라가며 제거 대상으로 표시 (BFS)
while (q.length) {
  const p = q.pop();
  if (!near(p, br, bg, bb)) continue;
  out[p] = 1;
  const i = p % W, j = (p / W) | 0;
  if (i &gt; 0) push(p-1);  if (i &lt; W-1) push(p+1);
  if (j &gt; 0) push(p-W);  if (j &lt; H-1) push(p+W);
}</code></pre>
<p data-ke-size="size18"><span style="color: #000000; background-color: #dddddd;">5-1. tolerance 한 줄 때문에 얼굴이 통째로 날아갔다</span></p>
<p data-ke-size="size16">"배경색과 비슷한가"를 판정하는 <code>near()</code> 함수를 처음에는 이렇게 썼습니다.</p>
<pre class="javascript" data-ke-type="codeblock" data-ke-language="javascript"><code>// 세 채널 차이의 &#x27;합&#x27;이 105 미만이면 배경으로 판정
const near = (p, r, g, b) =&gt; {
  const k = p * 4;
  return Math.abs(d[k]-r) + Math.abs(d[k+1]-g) + Math.abs(d[k+2]-b) &lt; 105;
};</code></pre>
<p data-ke-size="size16">테스트해 보니 캐릭터 <b>얼굴이 통째로 투명해졌습니다.</b> 계산해 보니 원인이 명확했습니다.</p>
<pre class="plain" data-ke-type="codeblock" data-ke-language="plain"><code>얼굴 살구색 (255, 220, 190)
흰 배경    (255, 255, 255)
차이의 합 = 0 + 35 + 65 = 100  →  105 미만  →  배경으로 판정</code></pre>
<p data-ke-size="size16"><b>합(sum)이 아니라 채널별 최대 차이(max)</b>로 바꿔서 해결했습니다.</p>
<pre class="javascript" data-ke-type="codeblock" data-ke-language="javascript"><code>// 어느 한 채널이라도 26 이상 차이나면 배경이 아니다
const near = (p, r, g, b) =&gt; {
  const k = p * 4;
  return Math.max(Math.abs(d[k]-r), Math.abs(d[k+1]-g), Math.abs(d[k+2]-b)) &lt; 26;
};</code></pre>
<p data-ke-size="size16">합으로 판정하면 <b>한 채널만 크게 다른 색</b>(살구색처럼 R은 같고 G·B만 다른 경우)을 놓칩니다. 색 거리를 잴 때는 맨해튼 거리보다 체비셰프 거리(최대 차이)가 안전한 경우가 있다는 걸 배웠습니다.</p>
<p data-ke-size="size18"><span style="color: #000000; background-color: #dddddd;">5-2. 안쪽 구멍 처리</span></p>
<p data-ke-size="size16">바깥에서만 채우면 <b>선으로 막힌 안쪽 빈 공간</b>(팔과 몸 사이, 트윈테일 사이 등)이 남습니다. 그렇다고 배경색과 같은 픽셀을 전부 지우면 캐릭터 안의 흰 옷까지 사라집니다. 그래서 <b>크기로 구분</b>했습니다.</p>
<pre class="javascript" data-ke-type="codeblock" data-ke-language="javascript"><code>// 바깥 채우기가 닿지 못한 영역 중, 작은 구멍만 제거
const holeMax = W * H * .06;          // 이미지 면적의 6% 미만만
if (cell.length &lt; holeMax) for (const q of cell) out[q] = 1;

// 가장자리 알파 페더링 (계단현상 완화)
if (n) d[p*4 + 3] = 255 - n * 45;</code></pre>

<h4 data-ke-size="size20"><span style="color: #000000; background-color: #f6e199;">6. 모바일 대응 - 카톡 인앱 브라우저와의 싸움</span></h4>
<p data-ke-size="size16">&nbsp;</p>
<p data-ke-size="size16">링크를 카톡으로 공유하는 게 목표였는데, <b>인앱 브라우저에서 글자만 1.5배로 커지는</b> 문제가 있었습니다. iOS WebKit의 <b>Text Autosizing(Font Boosting)</b> 때문입니다. 처음에는 이렇게 했는데 안 먹혔습니다.</p>
<pre class="css" data-ke-type="codeblock" data-ke-language="css"><code>html { -webkit-text-size-adjust: none; }    /* 안 됨 */
html { -webkit-text-size-adjust: 100%; }    /* 이것도 안 됨 */</code></pre>
<p data-ke-size="size16">결국 두 가지를 같이 적용해서 해결했습니다.</p>
<pre class="css" data-ke-type="codeblock" data-ke-language="css"><code>/* (1) none + !important, html과 body 양쪽에 */
html, body {
  -webkit-text-size-adjust: none !important;
  -moz-text-size-adjust: none !important;
  text-size-adjust: none !important;
}

/* (2) max-height 트릭
   WebKit은 &#x27;높이 제약이 걸린 요소&#x27;를 Font Boosting 대상에서 제외한다.
   사실상 무제한 값이라 레이아웃에는 영향이 없고 boost만 꺼진다. */
* {
  -webkit-text-size-adjust: none !important;
  font-synthesis: none;
  max-height: 1000000px;
}</code></pre>
<p data-ke-size="size16">(2)번이 결정적이었습니다. <code>text-size-adjust</code>만으로는 Font Boosting이 막히지 않는다는 걸 몰랐습니다.</p>
<p data-ke-size="size18"><span style="color: #000000; background-color: #dddddd;">6-1. 스크롤할 때마다 미리보기 크기가 미묘하게 바뀜</span></p>
<p data-ke-size="size16">미리보기 높이를 <code>window.innerHeight * 1.1</code>로 제한했는데, 모바일은 스크롤 시 주소창이 접히며 <code>innerHeight</code>가 계속 변합니다. <b>높이를 폭과 기기 비율로만</b> 결정하도록 바꿔서 화면 높이와 무관하게 만들었습니다.</p>
<pre class="javascript" data-ke-type="codeblock" data-ke-language="javascript"><code>// const maxH = window.innerHeight * 1.1;   ← 스크롤 때마다 변함
// 폭만으로 높이를 결정
const w = Math.min(360, box), ar = S.device[1] / S.device[2], h = w / ar;</code></pre>
<p data-ke-size="size18"><span style="color: #000000; background-color: #dddddd;">6-2. 미리보기 위에서 스크롤이 안 됨</span></p>
<p data-ke-size="size16">드래그 편집 때문에 <code>touch-action: none</code>을 걸었더니, 화면을 거의 채우는 미리보기 위에서 스크롤이 먹통이었습니다. <b>선택 상태에 따라 동적으로 전환</b>했습니다.</p>
<pre class="javascript" data-ke-type="codeblock" data-ke-language="javascript"><code>const syncTouch = () =&gt; {
  cv.style.touchAction = (S.sel &amp;&amp; S.sel.t !== &#x27;item&#x27;) ? &#x27;none&#x27; : &#x27;pan-y&#x27;;
};
// 아무것도 선택 안 함        → pan-y (세로 스크롤 O)
// 과목 탭 (색·이름 편집만)    → pan-y (스크롤 O)
// 말풍선·캐릭터·시간표를 잡음 → none  (드래그해야 하니 스크롤 X)</code></pre>
<p data-ke-size="size18"><span style="color: #000000; background-color: #dddddd;">6-3. 캐시 때문에 수정이 반영 안 됨</span></p>
<p data-ke-size="size16">고쳐도 반영이 안 되길래 확인해 보니 브라우저가 예전 <code>app.js</code>를 쓰고 있었습니다. 배포할 때마다 버전 쿼리를 갱신하도록 했습니다.</p>

<h4 data-ke-size="size20"><span style="color: #000000; background-color: #f6e199;">7. 그 외 구현한 기능들</span></h4>
<p data-ke-size="size16">&nbsp;</p>
<ul data-ke-list-type="disc"><li><b>기기별 해상도 프리셋</b> : 아이폰 8부터 아이패드까지 10종. 저장 시 해당 해상도로 다시 렌더링합니다.</li><li><b>색상 커스텀</b> : 30색 팔레트 + 컬러 피커. 과목을 탭하면 박스 색, 빈 칸을 탭하면 선 색이 바뀝니다. 컬러 피커는 <code>&lt;input type="color"&gt;</code>를 투명하게 덮고 무지개 <code>conic-gradient</code>를 배경으로 깔아 한눈에 알아보게 했습니다.</li><li><b>글꼴 분리 선택</b> : 시간표용 / 말풍선용을 따로 고릅니다. 단, 요일·시간 라벨은 손그림 느낌 유지를 위해 글꼴을 고정했습니다.</li><li><b>말풍선 선 굵기 조절</b> : PNG 이미지라 선만 굵게 할 수 없습니다. 어두운 픽셀(선)만 추출한 레이어를 캐시해 두고, 2겹 × 16방향으로 미세하게 겹쳐 그려서 팽창 효과를 냈습니다.</li></ul>

<h4 data-ke-size="size20"><span style="color: #000000; background-color: #f6e199;">9. 마무리하며</span></h4>
<p data-ke-size="size16">&nbsp;</p>
<p data-ke-size="size16">이번 프로젝트에서 얻은 것들을 정리하면 이렇습니다.</p>
<p data-ke-size="size16"><b>1) 증상을 고치기 전에 측정하자</b></p>
<p data-ke-size="size16">선 굵기 문제를 네 번 고쳤는데 전부 틀렸습니다. 캔버스 픽셀을 직접 재 보니 렌더링은 처음부터 정상이었고 범인은 미리보기 축소였습니다. 추측으로 고치면 같은 자리를 계속 돕니다.</p>
<p data-ke-size="size16"><b>2) 라이브러리보다 도메인 지식이 강할 때가 있다</b></p>
<p data-ke-size="size16">OCR에 통째로 던졌으면 지금 정확도의 절반도 안 나왔을 겁니다. "에타는 수업명만 진하다", "수업 경계는 반드시 30분 단위다" 같은 구조에 대한 이해가 대부분의 정확도를 만들었습니다.</p>
<p data-ke-size="size16"><b>3) 고정 임계값은 언젠가 깨진다</b></p>
<p data-ke-size="size16"><code>if (v &lt; 135)</code> 같은 고정값은 다른 시간표에서 반드시 깨집니다. 배경 밝기, 글자 밝기 분포, 열 간격 중앙값처럼 <b>그 이미지에서 매번 계산</b>하는 값으로 바꾸고 나서야 안정됐습니다.</p>
<p data-ke-size="size16"><b>4) 자동화가 100%가 될 수 없다면, 수정 비용을 최소로</b></p>
<p data-ke-size="size16">OCR 오독은 어떻게 해도 남습니다. 그래서 미리보기에서 과목을 탭하면 바로 고칠 수 있게 만들었습니다. 100%를 못 만들면 95% + 쉬운 수정이 답이라고 생각했습니다.</p>
<p data-ke-size="size16"><b>5) 실기기 환경은 따로 공부해야 한다</b></p>
<p data-ke-size="size16">카톡 인앱 브라우저의 Font Boosting, 모바일 주소창 때문에 변하는 <code>innerHeight</code>, <code>touch-action</code>과 스크롤의 충돌 — 데스크톱 브라우저에서는 하나도 재현되지 않는 문제들이었습니다.</p>
